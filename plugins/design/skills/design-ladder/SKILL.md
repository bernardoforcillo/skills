# Design ladder

Level is scope, origin and multiplier — not craft. This skill reads work against those axes to coach and to staff; it does not rate people.

## Method

1. Place the work on **scope radius**: one team, adjacent teams, or the group.
2. Ask where the **problem came from**: assigned, found, or defined at strategy level.
3. Ask what **multiplier** came out: standards, coaching, systems, process.
4. Apply the per-level questions in `${CLAUDE_PLUGIN_ROOT}/skills/design/references/roles-and-levels.md` (Senior / Staff / Principal).
5. **Track glue work** (coordination, onboarding, documentation) by name and attribute it.
6. Say where the evidence is thin: only Intercom's and GitLab's public ladders were verified; Design Director / Head of Design has no primary source and is a house convention.

Never use the output to set pay or promotion. The `design-lead` agent can run it in isolation.
